## Goals and Background Context

### Goals

- 创建一个简洁高效的**跨平台**待办事项管理应用，提供流畅的任务管理体验
- 支持多维度任务组织（项目、标签、优先级、截止日期），满足个人和轻量团队协作需求
- 实现智能提醒系统（基于时间、地点、上下文），确保重要任务不被遗忘
- 提供直观的任务视图（列表、看板、日历、今日聚焦），适应不同工作场景
- 实现全平台数据同步（Web、移动端、桌面端）和离线优先架构
- **成功指标**：实现70%的月留存率，日活用户平均创建5个任务，任务完成率>60%

### Background Context

待办事项管理是刚需场景，市场上虽有众多竞品（Todoist、TickTick、Things等），但多数应用要么功能过于复杂（学习成本高）、要么过于简单（无法满足进阶需求）。本项目旨在打造一个**"刚刚好"的待办应用**：核心功能完善、操作极简流畅、视觉令人愉悦。我们的差异化优势在于**智能聚焦系统**：通过AI算法自动分析任务优先级，每日推荐"今日三件事"，帮助用户聚焦最重要的工作。MVP阶段面向个人用户，采用Freemium模式（基础功能免费，高级功能订阅），验证产品-市场契合度后再拓展团队协作功能。

## Requirements

### Functional

**FR1**: 用户可以快速创建任务，支持自然语言输入（如"明天下午3点开会"自动解析为任务+时间）

**FR2**: 任务支持多维度属性：标题、描述、截止日期、优先级（高/中/低）、项目分类、标签、子任务、附件

**FR3**: 用户可以创建项目来组织相关任务，项目支持颜色标识、图标、归档功能

**FR4**: 用户可以创建自定义标签（如@工作、@个人、@紧急），一个任务可添加多个标签

**FR5**: 系统提供多种任务视图：
- 收件箱：所有未分类任务
- 今日视图：今天需要完成的任务
- 下一步：按优先级和截止日期智能排序
- 项目视图：按项目分组
- 标签视图：按标签筛选
- 日历视图：按日期可视化展示
- 看板视图：拖拽式工作流（待办/进行中/已完成）

**FR6**: 系统实现智能提醒功能：
- 基于时间：截止日期前N小时/天提醒
- 基于地点：到达指定地点时提醒（移动端）
- 循环提醒：每天/每周/每月重复任务
- 智能推荐：根据历史习惯推荐提醒时间

**FR7**: 用户可以为任务添加子任务（最多3层嵌套），子任务完成进度显示在父任务上

**FR8**: 系统提供"今日聚焦"功能：每天早上推荐3个最重要的任务，基于截止日期、优先级、历史完成规律综合评估

**FR9**: 用户可以搜索任务（支持标题、描述、标签、项目全文搜索），并保存常用搜索为智能列表

**FR10**: 任务支持协作功能（高级功能）：分配给他人、评论、@提及、活动日志

**FR11**: 系统自动统计并展示生产力数据：完成任务数、完成率、连续打卡天数、项目进度、时间分布（按项目/标签）

**FR12**: 用户可以导入/导出任务（支持CSV、JSON、Todoist格式），迁移数据无障碍

### Non Functional

**NFR1**: 应用必须支持离线优先架构，所有操作离线可用，网络恢复后自动同步

**NFR2**: 跨平台数据同步延迟必须<2秒，冲突解决采用"最后写入优先"策略，并提供冲突提示

**NFR3**: 应用必须支持Web（桌面和移动浏览器）、iOS原生、Android原生、桌面端（Electron或Tauri）

**NFR4**: 任务创建和标记完成的响应时间必须<100ms，确保操作即时反馈

**NFR5**: 应用启动时间必须<2秒（首次）、<1秒（后续），确保快速进入工作状态

**NFR6**: 所有用户数据必须端到端加密（E2EE），服务器无法读取用户任务内容

**NFR7**: 应用必须支持完整的键盘快捷键操作（创建任务、标记完成、切换视图等），提升重度用户效率

**NFR8**: UI必须支持深色/浅色主题自动切换，并提供自定义主题色

**NFR9**: 代码测试覆盖率必须>85%（核心逻辑>95%），确保数据可靠性

**NFR10**: 应用包体积必须<5MB（移动端），首次加载时间<3秒（Web端）

## User Interface Design Goals

### Overall UX Vision

打造一个**"呼吸感"**的待办应用：界面极简克制，交互轻盈流畅，让用户专注于任务本身而非工具。核心设计理念是**"快速捕获，轻松管理"**：添加任务只需一键，查看任务一目了然，完成任务充满成就感。视觉风格追求**现代极简主义**：大量留白、柔和配色、微妙动画，营造平静专注的氛围。重度用户可通过键盘快捷键达到"无鼠标操作"，新手用户通过引导在3分钟内学会核心功能。

### Key Interaction Paradigms

1. **快速捕获优先**：
   - 应用打开默认焦点在"添加任务"输入框
   - 支持全局快捷键（Ctrl/Cmd+Shift+A）快速呼出添加窗口
   - 自然语言输入："明天3pm开会"自动识别时间
   - 移动端支持语音输入快速创建任务

2. **手势与快捷键双轨制**：
   - 移动端：左滑标记完成，右滑推迟，长按进入编辑
   - 桌面端：Space标记完成，Enter编辑，Delete删除，方向键导航
   - 拖拽排序和移动任务到不同项目

3. **智能上下文感知**：
   - 根据当前时间显示合适任务（早上显示今日任务，晚上显示明日计划）
   - 检测到重复模式自动建议循环任务（如连续3天9am创建"晨会"）
   - 识别任务之间的关联，自动建议添加到同一项目

4. **即时反馈与微交互**：
   - 任务完成播放愉悦的音效和打勾动画
   - 连续完成任务触发"连击"动画激励
   - 拖拽时提供触觉反馈（移动端震动）
   - 所有操作支持撤销（Ctrl/Cmd+Z）

### Core Screens and Views

1. **收件箱/今日视图（默认首页）**
   - 顶部："今日聚焦"卡片显示3个重要任务
   - 主列表：今日任务按优先级排序
   - 快速添加栏：底部固定输入框
   - 侧边栏（桌面）/底部导航（移动）：视图切换、项目、标签

2. **任务详情页**
   - 大标题编辑区（支持Markdown）
   - 属性区：截止日期、优先级、项目、标签（图标化展示）
   - 子任务列表（可折叠）
   - 备注区（富文本）
   - 附件区（文件上传）
   - 活动历史（协作时显示）

3. **项目视图**
   - 项目列表：卡片式布局，显示进度条、任务数、颜色标识
   - 项目详情：任务列表、项目描述、成员（协作版）
   - 新建项目：模板选择（工作项目/个人目标/旅行计划等）

4. **日历视图**
   - 月视图：每天显示任务数量，点击查看详情
   - 周视图：时间线展示，支持拖拽调整时间
   - 日视图：时间块展示，类似日程表
   - 支持与系统日历集成（导入节假日、生日等）

5. **看板视图**
   - 三列布局：待办 | 进行中 | 已完成
   - 拖拽任务在列之间移动
   - 支持自定义列（如"等待中"、"已搁置"）
   - 适合项目管理和工作流场景

6. **统计与回顾页**
   - 仪表盘：今日/本周/本月完成数、完成率、连续打卡
   - 生产力趋势图：完成任务数随时间变化
   - 项目/标签时间分配饼图
   - 成就徽章：首次完成、7天连续、100个任务等

7. **设置页**
   - 账号与同步：登录状态、同步设置、数据导出
   - 外观：主题（浅色/深色/自动）、主题色、字体大小
   - 通知：提醒方式、免打扰时段、声音
   - 高级：键盘快捷键自定义、智能功能开关、数据隐私

## Technical Assumptions

### Repository Structure
**Monorepo** - 使用Turborepo或Nx管理多平台代码

```
/packages
  /web          - Web应用（React）
  /mobile       - 移动端（React Native或Flutter）
  /desktop      - 桌面端（Electron/Tauri）
  /shared       - 共享逻辑（任务模型、同步引擎）
  /ui           - 共享UI组件库
/apps
  /api          - 后端API（可选，用于同步）
```

### Service Architecture
**离线优先 + 云同步架构**

**前端**：
- 所有数据本地存储（IndexedDB/SQLite）
- 离线操作全部可用
- 后台同步引擎处理数据同步

**后端（仅用于同步）**：
- RESTful API或GraphQL处理数据同步
- WebSocket实时推送（协作功能）
- 对象存储（附件）
- 端到端加密（服务器不可读取任务内容）

**技术栈**：
- **前端框架**：React 18 + TypeScript（Web/Desktop）
- **移动端**：React Native或Flutter（跨平台）
- **状态管理**：Zustand + TanStack Query
- **UI组件库**：Radix UI + Tailwind CSS
- **本地数据库**：IndexedDB（Web）/ SQLite（Native）
- **同步引擎**：自研CRDTs或Replicache
- **构建工具**：Vite（Web）/ Turbo（Monorepo）
- **后端**：Node.js + Fastify + PostgreSQL + Redis

### Testing Requirements
**全面测试策略**

1. **单元测试**（>90%覆盖率）：
   - 任务模型和业务逻辑
   - 同步引擎和冲突解决
   - 自然语言解析
   - 日期时间处理
   - 测试框架：Vitest + React Testing Library

2. **集成测试**：
   - 完整任务CRUD流程
   - 跨平台数据同步
   - 离线→在线场景
   - 多设备冲突解决

3. **E2E测试**（关键路径）：
   - 用户完整工作流（创建→管理→完成任务）
   - 多平台一致性测试
   - 性能基准测试
   - 测试框架：Playwright（Web）/ Detox（Mobile）

4. **性能测试**：
   - 10000+任务场景下的操作响应时间
   - 同步性能（1000条任务增量同步<2秒）
   - 内存占用和电池消耗（移动端）
   - Lighthouse CI（Web性能>90分）

### Additional Technical Assumptions and Requests

1. **自然语言解析**：
   - 使用Chrono.js或自研NLP引擎
   - 支持中文和英文日期时间识别
   - 示例："明天下午3点给张三打电话" → 任务+时间+标签

2. **同步引擎**：
   - 采用CRDTs（Conflict-free Replicated Data Types）
   - 或使用成熟方案：Replicache / RxDB / WatermelonDB
   - 支持离线编辑，在线自动合并
   - 冲突策略：最后写入优先（LWW）+ 用户可选手动解决

3. **智能聚焦算法**：
   - 优先级评分 = 截止日期紧迫度 × 0.4 + 用户设置优先级 × 0.3 + 历史完成规律 × 0.2 + 依赖关系 × 0.1
   - 每日推荐3个任务，避免过载
   - 机器学习优化（可选）：根据用户完成习惯调整权重

4. **端到端加密**：
   - 用户数据在本地加密后上传
   - 加密密钥基于用户密码派生（PBKDF2）
   - 服务器存储密文，无法解密
   - 端到端加密可选（Freemium高级功能）

5. **通知系统**：
   - Web：使用Notification API + Service Worker
   - 移动端：Firebase Cloud Messaging（FCM）/ APNs
   - 地理位置提醒：Geofencing API（需用户授权）

6. **数据持久化**：
   - Web：IndexedDB（使用Dexie.js封装）
   - 移动端：SQLite（使用WatermelonDB）
   - 桌面端：SQLite或本地文件系统

7. **部署方案**：
   - Web：Vercel / Netlify（前端）+ Railway / Fly.io（后端）
   - 移动端：App Store / Google Play
   - 桌面端：GitHub Releases（自动更新）

8. **开发环境**：
   - Node.js 20+
   - pnpm（Monorepo包管理）
   - Turborepo（构建编排）
   - Docker（本地开发环境）

9. **CI/CD**：
   - GitHub Actions自动化测试和部署
   - PR必须通过所有测试和Lint检查
   - 自动发布到预览环境
   - Main分支自动部署生产环境

## Epic 3: 跨平台同步与云服务

**Epic Goal**: 实现多设备数据同步、离线优先架构、冲突解决机制，交付完整的云服务体验。用户可以在多个设备间无缝切换，数据实时同步。

### Story 3.1: 用户认证系统

作为一个用户，
我想要创建账号并登录，
以便我可以同步数据到云端。

**Acceptance Criteria**:
1. 后端实现用户注册API：POST /api/auth/register
2. 后端实现用户登录API：POST /api/auth/login
3. JWT认证，Token有效期7天，支持刷新
4. 前端登录页：邮箱+密码，支持记住我
5. 支持第三方登录（可选）：Google / Apple Sign-In
6. 密码强度验证：至少8位，包含字母和数字
7. 忘记密码：邮箱验证码重置
8. 登录状态持久化，刷新页面保持登录

### Story 3.2: 同步引擎架构设计

作为一个开发者，
我想要设计高效的同步引擎，
以便支持多设备数据同步。

**Acceptance Criteria**:
1. 选择同步方案：CRDTs（自研）或成熟方案（Replicache）
2. 实现同步协议：
   - 客户端定期拉取服务端变更（Pull）
   - 本地变更批量推送到服务端（Push）
   - 使用版本向量（Vector Clock）检测冲突
3. 实现增量同步：只传输变更部分，减少流量
4. 实现同步队列：失败重试，指数退避
5. 同步状态显示：同步中/已同步/同步失败
6. 性能目标：1000条任务增量同步<2秒
7. 单元测试验证同步逻辑，模拟网络故障场景

### Story 3.3: 离线优先架构

作为一个用户，
我想要在无网络时也能使用应用，
以便我可以随时记录待办。

**Acceptance Criteria**:
1. 所有操作优先写入本地数据库（IndexedDB）
2. 操作立即返回，UI立即更新（乐观更新）
3. 后台同步引擎将本地变更上传到云端
4. 网络恢复时自动触发同步
5. 离线状态显示：顶部横幅"当前离线，数据将在联网后同步"
6. 离线期间的操作记录，上线后批量同步
7. Service Worker缓存所有静态资源，完全离线可用
8. 测试离线场景：开飞行模式，所有功能正常

### Story 3.4: 冲突解决机制

作为一个用户，
我想要系统自动解决多设备编辑冲突，
以便我不会丢失数据。

**Acceptance Criteria**:
1. 冲突检测：两个设备同时修改同一任务
2. 冲突解决策略：最后写入优先（LWW - Last Write Wins）
3. 特殊字段独立合并：
   - 标题/描述：取最新版本
   - 标签：合并去重
   - 子任务：合并列表
4. 冲突发生时记录日志，供用户查看
5. 提供"冲突历史"入口，显示被覆盖的版本
6. 用户可选择恢复历史版本
7. 单元测试覆盖各种冲突场景

### Story 3.5: 后端API实现

作为一个开发者，
我想要实现后端同步API，
以便客户端可以上传和下载数据。

**Acceptance Criteria**:
1. 实现API端点：
   - GET /api/sync/pull?since=timestamp：拉取变更
   - POST /api/sync/push：推送变更
   - GET /api/tasks：获取所有任务
   - POST /api/tasks：创建任务
   - PUT /api/tasks/:id：更新任务
   - DELETE /api/tasks/:id：删除任务
2. 数据库设计：PostgreSQL存储用户、任务、项目、标签
3. 软删除实现：deleted_at字段，支持恢复
4. API性能优化：分页、索引、缓存（Redis）
5. API文档：OpenAPI/Swagger自动生成
6. 速率限制：防止滥用（每分钟100请求）
7. 集成测试验证所有API端点

9. 性能测试：加密/解密1000条任务<1秒
