# 中国象棋游戏 Product Requirements Document (PRD)

## Goals and Background Context

### Goals

- 创建一个现代化的**Web端**中国象棋游戏应用，提供流畅的对弈体验
- 支持人机对弈（AI难度：初级、中级、高级、大师）和人人对弈（本地双人、在线对战）
- 实现智能AI引擎，基于Minimax算法与Alpha-Beta剪枝，响应时间<3秒
- 提供直观的棋盘界面，支持悔棋、复盘、棋谱保存和棋力分析功能
- 实现对局自动保存、历史棋谱管理和个人对弈统计追踪
- **成功指标**：实现65%的周留存率，平均对局时长>20分钟，AI对局完成率>70%

### Background Context

中国象棋是中华文化瑰宝，拥有数亿爱好者。当前市场上虽然存在多个象棋应用，但大多界面陈旧、AI水平参差不齐、缺乏现代化的学习辅助功能。本项目旨在创建一个现代化、用户友好的**Web端**象棋应用（响应式设计，支持桌面和移动浏览器），专注于纯粹的对弈体验和智能化辅助学习。我们的差异化优势在于**分级AI系统**：从入门级到大师级，满足不同水平棋手的需求，并提供**AI着法分析**功能，帮助玩家理解每一步棋的优劣。MVP阶段采用免费模式，验证用户留存假设后再考虑增值功能（如在线排位、高级AI等）。

## Requirements

### Functional

**FR1**: 用户可以选择游戏模式：人机对弈（选择AI难度：初级/中级/高级/大师）、本地双人对弈、在线匹配对战

**FR2**: 系统实现完整的中国象棋规则引擎，包括：走子规则、吃子规则、将帅不能照面、长将判和、困毙判负等所有标准规则

**FR3**: 用户通过点击或拖拽方式移动棋子，系统实时验证走法合法性，非法走子显示提示并禁止移动

**FR4**: 人机对弈模式下，AI在3秒内计算并执行走子，难度等级影响搜索深度和评估精度

**FR5**: 用户可以在对局中使用悔棋功能（人机模式支持悔棋，双人模式需对方同意），系统保存最近100步棋谱

**FR6**: 系统提供着法提示功能：
- 一级提示：高亮显示当前所有合法走子位置
- 二级提示：推荐3个最佳着法位置（不显示具体走法）
- 三级提示：直接显示AI推荐的最佳走法及评分

**FR7**: 对局结束后（将死、困毙、认输、和棋），系统自动保存完整棋谱到本地，并显示对局复盘界面

**FR8**: 用户可以浏览历史棋谱，支持逐步回放、快进/快退、跳转到关键回合、添加注释

**FR9**: 系统追踪并展示对弈统计数据：总对局数、胜率、平均对局时长、各难度AI胜率、连胜记录、棋力评级

**FR10**: 用户可以导入/导出棋谱（支持PGN格式和自定义JSON格式），分享精彩对局

**FR11**: 在线对战模式下，支持实时匹配（按棋力评级匹配）、好友对战（房间码邀请）、观战功能

**FR12**: 系统提供AI着法分析功能，对局结束后分析每一步棋的评分变化，标注失误、妙手和关键转折点

### Non Functional

**NFR1**: AI走子响应时间必须在3秒内完成（中级难度），UI交互响应时间<100ms，确保流畅对弈体验

**NFR2**: 应用必须支持桌面浏览器（Chrome/Firefox/Safari/Edge最新两个版本）和移动浏览器的响应式设计

**NFR3**: 应用必须支持离线模式（PWA），用户可在无网络环境下进行人机对弈和本地双人对弈

**NFR4**: 所有用户数据（对局历史、棋谱、统计信息）存储在客户端IndexedDB，在线对战数据存储在云端

**NFR5**: 棋盘渲染必须支持自适应缩放，在移动端和桌面端都能清晰显示棋子和棋盘

**NFR6**: 应用包体积<1MB（gzipped），首次加载时间<4秒（4G网络）

**NFR7**: 代码必须通过ESLint检查，核心逻辑（规则引擎、AI算法）测试覆盖率>90%

**NFR8**: 应用必须支持键盘操作（方向键移动光标、Enter确认、快捷键），满足无障碍访问基础要求

**NFR9**: 在线对战延迟必须<200ms，支持断线重连，保证对局连续性

**NFR10**: AI引擎运行在Web Worker中，不阻塞主线程，确保UI始终可响应

## User Interface Design Goals

### Overall UX Vision

打造一个**古典优雅、现代流畅**的象棋对弈体验。UI设计遵循"棋盘为王"原则：棋盘是绝对视觉焦点，采用传统中国象棋美学（木纹棋盘、立体棋子、毛笔字体），同时融合现代UI设计理念（流畅动画、清晰层次、直观操作）。核心设计目标：让新手用户在5秒内理解如何开始对弈，让高手用户能专注于棋局本身，达到"忘记界面存在"的沉浸状态。

### Key Interaction Paradigms

1. **点击/拖拽双模式**：
   - 点击模式：点击棋子→点击目标位置
   - 拖拽模式：拖动棋子到目标位置
   - 用户可在设置中选择偏好模式，默认支持两种模式共存

2. **智能走子提示**：
   - 选中棋子时，自动高亮所有合法走子位置（淡绿色圆点）
   - 鼠标悬停目标位置时，显示虚影预览
   - 非法走子尝试时，轻微抖动动画提醒

3. **对局状态即时反馈**：
   - 将军时播放提示音效，被将军方棋盘边框红色闪烁
   - 吃子时播放音效，棋子带缓动动画消失
   - AI思考时显示"对方思考中..."加载动画

4. **渐进式功能披露**：
   - 新手模式：显示走子提示、着法建议
   - 高手模式：隐藏所有辅助，纯净棋盘
   - 模式可在设置中切换

### Core Screens and Views

1. **欢迎/主菜单界面**
   - 中心显示"开始对弈"按钮和模式选择（人机/双人/在线）
   - 显示"继续上局"卡片（如有未完成对局）
   - 底部显示对弈统计摘要（总对局数、胜率、棋力评级）
   - 侧边栏：棋谱管理、统计、设置入口

2. **对弈主界面**
   - 9×10象棋棋盘（视觉焦点，占屏幕70%）
   - 顶部信息栏：对手信息（AI难度/玩家昵称）、计时器、当前回合数
   - 侧边栏（桌面）/底部栏（移动）：悔棋、提示、认输、求和按钮
   - 走子历史面板（可展开/收起）：显示完整着法记录

3. **对局结束界面**
   - 显示胜负结果和原因（将死/超时/认输等）
   - 展示对局统计：总步数、用时、吃子数、AI评分（如有）
   - 操作按钮：复盘分析、保存棋谱、再来一局、返回主菜单

4. **复盘分析界面**
   - 棋盘居中，支持逐步回放（上一步/下一步/自动播放）
   - 进度条显示对局进程，可拖动跳转
   - AI评分曲线图（如有分析数据），标注关键转折点
   - 着法列表显示每一步的评分、时长、注释

5. **棋谱管理界面**
   - 列表显示所有历史对局，支持按日期/胜负/对手筛选
   - 每个对局显示缩略信息：日期、对手、结果、步数
   - 操作：查看复盘、删除、导出、分享

6. **统计界面**
   - 总体数据看板：总对局数、胜率、平均对局时长、棋力评级
   - 难度分级统计：各AI难度胜率、对局数、进步曲线
   - 对弈热力图：按日期显示对局活跃度

7. **在线对战界面**
   - 匹配等待动画，显示"正在匹配棋力相近的对手..."
   - 对手信息卡片：昵称、棋力评级、胜率
   - 聊天面板（可选）：发送预设短语或自定义消息
   - 观战人数显示（如有观战者）

### Accessibility

**标准：WCAG AA**

- 色彩对比度至少达到4.5:1（文本）和3:1（UI组件）
- 提供高对比度主题，棋子和棋盘使用强对比色
- 所有交互元素支持键盘访问（方向键移动光标、Enter确认、Tab切换）
- 为屏幕阅读器提供ARIA标签（"炮五平六"、"车在第5行第8列"）
- 支持字体缩放，棋子大小可调整（小/中/大）

### Branding

由于这是新产品，暂无现有品牌资产。建议的品牌方向：

**色彩方案**：
- 主色：古铜色 (#8B4513) - 代表传统与文化底蕴
- 辅助色：朱砂红 (#C8442C) - 用于红方棋子
- 辅助色：墨玉黑 (#2C2C2C) - 用于黑方棋子
- 强调色：金色 (#D4AF37) - 用于高亮和重要提示
- 背景色：米白色 (#F5F1E8) - 营造宣纸质感

**字体**：
- 棋子文字使用楷书字体（思源宋体/方正楷体）彰显传统
- 界面文本使用黑体（思源黑体）保证现代感和可读性
- 走子记录使用等宽字体确保对齐

**视觉元素**：
- 棋盘使用木纹纹理贴图，营造真实感
- 棋子使用渐变和阴影，模拟立体效果
- 动画遵循缓入缓出（ease-in-out）曲线，模拟物理运动
- 走子路径使用贝塞尔曲线动画，自然流畅

### Target Device and Platforms

**Web Responsive（响应式Web）**

- **桌面浏览器**：1280×720及以上分辨率，Chrome/Firefox/Safari/Edge最新两个版本
- **平板设备**：768×1024（横屏/竖屏），iPad、Android平板
- **移动设备**：375×667及以上，iOS Safari、Android Chrome
- **PWA特性**：可添加到主屏幕，离线可用（人机对弈），全屏沉浸式体验

**响应式断点**：
- 移动端 (<768px)：棋盘占满宽度，控制按钮在底部，走子历史可折叠
- 平板 (768px-1024px)：棋盘居中，侧边栏变为抽屉式
- 桌面 (>1024px)：经典布局，棋盘居中，信息面板在侧边

## Technical Assumptions

### Repository Structure
**Monorepo** - 单一仓库包含前端代码、AI引擎、测试、构建配置和文档

### Service Architecture
**前后端分离架构（前端PWA + 后端API）**

**前端**：
- 纯前端单页应用（SPA），负责UI渲染、本地对局、AI计算
- 离线模式支持人机对弈和本地双人
- PWA Service Worker处理离线缓存

**后端（仅在线对战需要）**：
- WebSocket服务器处理实时对战匹配和消息推送
- REST API处理用户认证、棋谱同步、排行榜
- 数据库存储用户信息、在线棋谱、对战记录

**技术栈**：
- **前端框架**：React 18 + TypeScript
- **状态管理**：Zustand（游戏状态）+ React Query（服务端状态）
- **UI组件库**：Tailwind CSS + Shadcn/ui
- **Canvas渲染**：Konva.js（高性能棋盘渲染）
- **构建工具**：Vite（快速开发体验）
- **PWA工具**：Workbox（Service Worker管理）
- **后端**（MVP可选）：Node.js + Express + Socket.io + PostgreSQL

### Testing Requirements
**Full Testing Pyramid（完整测试金字塔）**

1. **单元测试**（90%覆盖率）：
   - 象棋规则引擎验证（所有走子规则、胜负判定）
   - AI算法验证（评估函数、搜索算法）
   - 棋谱解析和生成
   - 测试框架：Vitest + React Testing Library

2. **集成测试**：
   - 完整对局流程（开始→走子→结束）
   - AI对弈流程
   - 悔棋、复盘功能
   - IndexedDB持久化
   - Web Worker通信

3. **E2E测试**（关键路径）：
   - 人机对弈完整流程
   - 本地双人对弈流程
   - 棋谱保存和复盘
   - 多设备响应式测试
   - 测试框架：Playwright

4. **性能测试**：
   - AI响应时间基准测试（各难度必须在3秒内）
   - 棋盘渲染性能（60fps）
   - 内存占用测试（长时间对局）
   - Lighthouse CI集成（性能分数>85）

### Additional Technical Assumptions and Requests

1. **象棋规则引擎**：
   - 使用位棋盘（Bitboard）或数组表示棋盘状态
   - 实现所有标准规则：走子、吃子、将帅照面、长将、困毙
   - 支持FEN记法（Forsyth-Edwards Notation变体）
   - 走法生成器：生成所有合法走法列表

2. **AI引擎实现**：
   - 算法：Minimax + Alpha-Beta剪枝
   - 难度分级：
     - 初级：搜索深度2层，简化评估函数
     - 中级：搜索深度4层，标准评估函数
     - 高级：搜索深度6层，增强评估函数
     - 大师：搜索深度8层，开局库+残局库
   - 评估函数：棋子价值、位置价值、机动性、威胁度
   - AI在Web Worker中运行，避免UI卡顿

3. **棋谱格式**：
   - 主要格式：自定义JSON（包含完整元数据）
   - 导入/导出：支持PGN格式（便于与其他软件互通）
   - 棋谱包含：对局信息、着法列表、时间戳、AI评分（可选）

4. **数据持久化策略**：
   - 当前对局状态：LocalStorage（快速读写）
   - 历史棋谱：IndexedDB（支持大量棋谱存储）
   - 用户设置：LocalStorage
   - 在线数据：云端数据库 + 本地缓存

5. **在线对战架构**（MVP可延后）：
   - WebSocket实时通信
   - 房间管理系统（匹配、邀请、观战）
   - 断线重连机制
   - 防作弊：服务端验证所有走法

6. **部署方案**：
   - 前端：静态网站托管（Vercel / Netlify）
   - 后端（如有）：云服务器（AWS / 阿里云）
   - CDN加速
   - Gzip/Brotli压缩

7. **开发环境要求**：
   - Node.js 18+
   - 包管理器：pnpm
   - Git + GitHub
   - VS Code + ESLint + Prettier

8. **CI/CD流程**：
   - GitHub Actions自动化测试
   - PR合并前必须通过所有测试
   - 自动部署到预览环境
   - Main分支自动部署到生产环境
