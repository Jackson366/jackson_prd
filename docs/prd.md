# 数独游戏 Product Requirements Document (PRD)

## Goals and Background Context

### Goals

- 创建一个现代化的**Web端**数独游戏应用，提供流畅的游戏体验
- 支持多种难度级别（简单、中等、困难、专家），基于逻辑技巧复杂度分级
- 实现智能数独谜题生成算法，确保每个谜题有唯一解（生成时间<2秒）
- 提供直观的用户界面，支持笔记模式、撤销/重做功能、错误高亮和智能提示
- 实现进度自动保存和游戏统计追踪（完成率、平均用时、连续游戏天数）
- **成功指标**：实现70%的次日留存率，平均会话时长>15分钟，谜题完成率>60%

### Background Context

数独是全球最受欢迎的逻辑益智游戏之一，拥有广泛的用户基础。当前市场上虽然存在多个数独应用，但许多应用要么界面过时、要么充斥广告、要么缺乏智能辅助功能。本项目旨在创建一个现代化、用户友好的**Web端**数独游戏应用（响应式设计，支持桌面和移动浏览器），专注于纯粹的游戏体验和渐进式智能辅助。我们的差异化优势在于**分级智能提示系统**：从基础错误检测到高级逻辑技巧提示，帮助不同水平玩家提升技能而非直接给出答案。MVP阶段采用免费模式，验证用户留存假设后再考虑增值功能。

## Requirements

### Functional

**FR1**: 用户可以选择四种难度级别（简单、中等、困难、专家）开始新游戏，每个难度级别基于所需逻辑技巧复杂度定义

**FR2**: 系统自动生成有唯一解的数独谜题，生成时间不超过2秒，使用回溯算法确保解的唯一性

**FR3**: 用户可以点击空格输入1-9的数字，系统实时验证输入合法性（行/列/宫不重复）

**FR4**: 用户可以为任意空格启用"笔记模式"，在单元格中标记多个候选数字（1-9的小字标注）

**FR5**: 用户可以随时撤销/重做操作，系统保存最近50步操作历史

**FR6**: 系统提供三级智能提示功能：
- 一级提示：高亮显示当前填写错误的单元格
- 二级提示：指出某个单元格可以使用的逻辑技巧类型（如"唯一候选数"、"隐性单一"）
- 三级提示：显示具体单元格的正确数字及详细推理过程

**FR7**: 用户离开或刷新页面时，系统自动保存当前游戏进度（使用LocalStorage），返回时可继续游戏

**FR8**: 系统追踪并展示游戏统计数据：总完成谜题数、各难度最佳用时、连续游戏天数、当前连胜记录

**FR9**: 用户完成谜题后，系统显示庆祝动画、用时统计和难度评级，并提供"开始新游戏"选项

**FR10**: 用户可以随时暂停游戏，暂停时隐藏棋盘并停止计时

### Non Functional

**NFR1**: 谜题生成响应时间必须在2秒内完成，UI交互响应时间<100ms，确保流畅体验

**NFR2**: 应用必须支持桌面浏览器（Chrome/Firefox/Safari/Edge最新两个版本）和移动浏览器的响应式设计

**NFR3**: 应用必须支持离线模式（PWA），用户可在无网络环境下继续游戏

**NFR4**: 所有用户数据（游戏进度、统计信息）存储在客户端LocalStorage，无需服务器

**NFR5**: UI必须支持色盲友好配色方案（可选主题），单元格区分不依赖纯色彩

**NFR6**: 应用包体积<500KB（gzipped），首次加载时间<3秒（4G网络）

**NFR7**: 代码必须通过ESLint检查，测试覆盖率>80%（单元测试+集成测试）

**NFR8**: 应用必须支持键盘操作（方向键导航、数字键输入、快捷键），满足无障碍访问基础要求

## User Interface Design Goals

### Overall UX Vision

打造一个**简洁、专注、沉浸式**的数独游戏体验。UI设计遵循"内容优先"原则：棋盘是视觉焦点，所有控制项围绕棋盘组织且不干扰游戏流。采用**渐进式披露**设计模式，初级用户看到的是极简界面，高级功能（统计、设置）隐藏在明确的入口后。整体风格为**现代极简风格**，使用柔和配色降低长时间游戏的视觉疲劳，提供深色/浅色主题切换。核心设计目标：让玩家在3秒内理解如何开始游戏，在游戏过程中达到"心流"状态。

### Key Interaction Paradigms

1. **点击优先，键盘增强**：
   - 主要交互通过触摸/鼠标点击完成（选择单元格→点击数字按钮）
   - 键盘用户可使用方向键导航+数字键输入（无需鼠标）
   - 支持快捷键：`Ctrl+Z`撤销、`H`提示、`N`笔记模式

2. **上下文感知的智能高亮**：
   - 选中单元格时，自动高亮同行/同列/同宫的相关单元格
   - 选中数字后，高亮棋盘上所有相同数字（帮助发现冲突）
   - 错误单元格用红色高亮，冲突关系用虚线连接

3. **渐进式提示系统**：
   - 提示按钮显示剩余提示次数（限制使用避免依赖）
   - 每次提示前确认："使用一级提示？（剩余5次）"
   - 提示后提供"了解更多"入口，解释使用的逻辑技巧

4. **即时反馈**：
   - 输入数字时即时验证，错误立即显示微动画提醒
   - 完成一行/列/宫时播放微妙的成就音效
   - 进度自动保存时显示淡入淡出的"已保存"提示

### Core Screens and Views

1. **欢迎/主菜单界面**
   - 中心显示"开始新游戏"按钮和难度选择
   - 展示"继续上次游戏"卡片（如有未完成游戏）
   - 底部显示游戏统计摘要（完成数、连续天数）

2. **游戏主界面**
   - 9×9数独棋盘（视觉焦点，占屏幕60%）
   - 顶部信息栏：难度、计时器、暂停/退出按钮
   - 底部控制栏：数字输入按钮（1-9）、橡皮擦、笔记模式切换
   - 侧边栏（桌面）/抽屉（移动）：撤销/重做、提示、新游戏

3. **完成庆祝界面**
   - 全屏动画庆祝效果
   - 显示用时、难度评级、个人最佳对比
   - 操作按钮：分享成绩、开始新游戏、返回主菜单

4. **统计界面**
   - 总体数据看板：总完成数、总游戏时长、平均完成率
   - 难度分级统计：各难度最佳用时、完成数、进步曲线
   - 连续游戏日历热力图

5. **设置界面**
   - 外观设置：主题（浅色/深色/色盲友好）、字体大小
   - 游戏设置：错误高亮开关、自动笔记开关、音效开关
   - 数据管理：清除本地数据、导出统计

### Accessibility

**标准：WCAG AA**

- 色彩对比度至少达到4.5:1（文本）和3:1（UI组件）
- 提供色盲友好主题，使用形状/图案辅助区分（不仅依赖颜色）
- 所有交互元素支持键盘访问，焦点状态清晰可见
- 为屏幕阅读器提供ARIA标签（"第3行第5列，当前值为空"）
- 支持字体缩放（浏览器默认缩放不破坏布局）

### Branding

由于这是新产品，暂无现有品牌资产。建议的品牌方向：

**色彩方案**：
- 主色：深邃蓝色 (#2C3E50) - 代表逻辑与专注
- 强调色：活力橙色 (#E67E22) - 用于高亮和CTA
- 成功色：柔和绿色 (#27AE60) - 完成和正确反馈
- 错误色：柔和红色 (#E74C3C) - 错误提示

**字体**：
- 数字使用等宽字体（JetBrains Mono / Roboto Mono）确保对齐
- 界面文本使用无衬线字体（Inter / SF Pro）保证现代感

**视觉元素**：
- 圆角设计（8px border-radius）传达友好感
- 微妙阴影和渐变（避免纯扁平化）增加层次感
- 动画遵循Material Design缓动曲线（流畅不突兀）

### Target Device and Platforms

**Web Responsive（响应式Web）**

- **桌面浏览器**：1280×720及以上分辨率，Chrome/Firefox/Safari/Edge最新两个版本
- **平板设备**：768×1024（横屏/竖屏），iPad、Android平板
- **移动设备**：375×667及以上，iOS Safari、Android Chrome
- **PWA特性**：可添加到主屏幕，离线可用，全屏沉浸式体验

**响应式断点**：
- 移动端 (<768px)：单列布局，数字按钮全宽，控制项在底部
- 平板 (768px-1024px)：数字按钮分两行，侧边栏变为抽屉
- 桌面 (>1024px)：经典布局，棋盘居中，控制项在侧边栏

## Technical Assumptions

### Repository Structure
**Monorepo** - 单一仓库包含前端代码、测试、构建配置和文档

### Service Architecture
**纯前端单体应用（Static PWA）**

- 无后端服务器，所有逻辑在客户端运行
- 数独生成算法使用Web Worker运行（避免阻塞UI线程）
- 数据持久化使用浏览器LocalStorage + IndexedDB
- PWA Service Worker处理离线缓存和资源管理

**技术栈**：
- **前端框架**：React 18 + TypeScript
- **状态管理**：Zustand（轻量级，适合游戏状态）
- **UI组件库**：Tailwind CSS（快速响应式开发）
- **构建工具**：Vite（快速开发体验）
- **PWA工具**：Workbox（Service Worker管理）

### Testing Requirements
**Full Testing Pyramid（完整测试金字塔）**

1. **单元测试**（80%覆盖率）：
   - 数独生成算法验证（确保唯一解）
   - 游戏逻辑（输入验证、撤销/重做）
   - 工具函数（得分计算、难度评估）
   - 测试框架：Vitest + React Testing Library

2. **集成测试**：
   - 用户游戏流程（开始→填写→完成）
   - LocalStorage持久化
   - Web Worker通信

3. **E2E测试**（关键路径）：
   - 完整游戏流程测试
   - 多设备响应式测试
   - 离线模式测试
   - 测试框架：Playwright

4. **性能测试**：
   - 谜题生成时间基准测试（必须<2秒）
   - Lighthouse CI集成（性能分数>90）

### Additional Technical Assumptions and Requests

1. **数独生成算法**：
   - 使用回溯算法生成完整棋盘
   - 随机挖空策略（简单：46-50空格，中等：41-45，困难：36-40，专家：32-35）
   - 唯一解验证使用约束传播+回溯求解器
   - 算法在Web Worker中运行，避免UI卡顿

2. **智能提示实现**：
   - 一级提示：基于当前棋盘状态的规则验证
   - 二级提示：检测裸单、隐性单一、指向对等技巧
   - 三级提示：调用求解器获取下一步最佳解及推理路径

3. **数据持久化策略**：
   - 当前游戏状态：LocalStorage（快速读写）
   - 历史统计数据：IndexedDB（支持大量历史记录）
   - 设置偏好：LocalStorage

4. **部署方案**：
   - 静态网站托管（Vercel / Netlify / GitHub Pages）
   - CDN加速
   - Gzip/Brotli压缩
   - 支持自定义域名

5. **开发环境要求**：
   - Node.js 18+
   - 包管理器：pnpm（快速、节省空间）
   - Git + GitHub
   - VS Code + ESLint + Prettier

6. **CI/CD流程**：
   - GitHub Actions自动化测试
   - PR合并前必须通过所有测试
   - 自动部署到预览环境
   - Main分支自动部署到生产环境

## Epic 3: 智能辅助与进阶功能

**Epic Goal**: 实现差异化的分级智能提示系统、完整的游戏统计追踪和PWA离线支持，交付具有竞争力的最终产品。用户可以通过智能提示学习数独技巧，并通过统计数据追踪个人进步。

### Story 3.1: 一级提示 - 错误检测

作为一个新手玩家，
我想要系统提示我哪些格子填错了，
以便我可以纠正错误继续游戏。

**Acceptance Criteria**:
1. 添加"提示"按钮（💡图标）到游戏界面
2. 点击提示按钮，显示提示级别选择："检测错误（免费）"、"逻辑提示（剩余5次）"、"直接答案（剩余3次）"
3. 选择"检测错误"，高亮所有与最终解不符的单元格（红色闪烁动画）
4. 提示后显示消息："发现3处错误，已标红显示"
5. 一级提示不消耗限制次数（无限使用）
6. 如无错误，显示："太棒了！目前没有错误。"
7. 单元测试：验证错误检测逻辑准确性

### Story 3.2: 二级提示 - 逻辑技巧指导

作为一个进阶玩家，
我想要系统指导我可以使用什么逻辑技巧，
以便我可以学习并提升解题能力。

**Acceptance Criteria**:
1. 实现逻辑技巧检测器：裸单（Naked Single）、隐性单一（Hidden Single）、裸对/三（Naked Pairs/Triples）
2. 选择"逻辑提示"，系统分析当前棋盘，找到可使用的最简单技巧
3. 高亮相关单元格和区域，显示提示文字："第3行第5列可以使用'隐性单一'技巧"
4. 提供"查看详解"按钮，展开详细推理过程（如"第3行中，数字7只能出现在这个位置"）
5. 二级提示每局限制5次使用，消耗后按钮显示"提示已用完"
6. 提示次数限制保存在游戏状态中，新游戏重置
7. 实现至少3种常用逻辑技巧的检测算法

### Story 3.3: 三级提示 - 直接答案

作为一个卡住的玩家，
我想要系统直接告诉我下一步填什么，
以便我可以继续游戏而不被完全困住。

**Acceptance Criteria**:
1. 选择"直接答案"，系统调用求解器找到下一步最优解
2. 高亮目标单元格，直接填入正确数字（绿色闪烁动画）
3. 显示解释："已为您填入第5行第7列的数字3"
4. 三级提示每局限制3次使用，消耗后禁用
5. 使用三级提示会在统计中标记（影响"完美完成"徽章）
6. 确认对话框："使用直接答案会降低得分，确认使用？"
7. 求解器优先填写逻辑简单的单元格（避免暴露高级技巧）

### Story 3.4: 游戏统计数据追踪

作为一个玩家，
我想要看到我的游戏统计数据，
以便我可以追踪自己的进步。

**Acceptance Criteria**:
1. 实现统计数据模型：总完成数、总游戏时长、各难度完成数、各难度最佳用时、连续游戏天数、使用提示次数
2. 每次完成游戏时，更新统计数据并保存到IndexedDB
3. 创建`<StatsPage>`页面，从主菜单进入
4. 显示总体数据看板：总完成数（大字显示）、总游戏时长、平均完成率
5. 显示难度分级表格：各难度的完成数、最佳用时、平均用时
6. 显示连续游戏日历热力图（类似GitHub贡献图）
7. 统计数据支持导出为JSON文件

### Story 3.5: 完成庆祝与成就系统

作为一个玩家，
我想要完成游戏时看到精彩的庆祝效果，
以便我可以获得成就感。

**Acceptance Criteria**:
1. 完成游戏时播放全屏彩纸动画（confetti effect）
2. 显示完成统计：用时、难度、是否刷新个人最佳、使用提示次数
3. 根据表现显示评级：⭐（使用3次三级提示）、⭐⭐（使用1-2次）、⭐⭐⭐（未使用提示）
4. 显示进步提示："比上次快了2分钟！"或"这是你第10个完成的谜题！"
5. 添加"分享成绩"按钮，生成分享图片（包含用时和评级）
6. 提供"再来一局"和"返回主页"按钮
7. 庆祝Modal支持键盘关闭（ESC键）

### Story 3.6: 进度自动保存与恢复

作为一个玩家，
我想要关闭浏览器后再次打开能继续未完成的游戏，
以便我可以随时中断和恢复游戏。

**Acceptance Criteria**:
1. 游戏状态变化时（每次输入后），自动保存到LocalStorage
2. 保存的状态包括：谜题、用户输入、笔记、操作历史、开始时间、累计用时、提示使用次数
3. 应用启动时，检测LocalStorage中是否有未完成游戏
4. 如有未完成游戏，主页显示"继续上次游戏"卡片（显示难度和已用时间）
5. 点击"继续游戏"，恢复到上次中断的状态（包括笔记和历史记录）
6. 游戏完成后，自动清除保存的进度
7. 设置中提供"放弃当前游戏"按钮，手动清除进度

作为一个移动端玩家，
我想要在没有网络的情况下也能玩游戏，
以便我可以在地铁、飞机上打发时间。

**Acceptance Criteria**:
1. 配置Workbox Service Worker，缓存所有静态资源（HTML、CSS、JS、字体）
2. 实现离线fallback页面，网络断开时显示"离线模式"提示
3. 游戏核心功能在离线状态下完全可用（生成谜题、游戏、保存进度）
4. 配置PWA manifest.json：应用名称、图标（192×192、512×512）、主题色、显示模式（standalone）
5. 添加"添加到主屏幕"提示（首次访问3天后显示）
6. Service Worker更新策略：新版本发布时提示用户刷新
7. 在Chrome DevTools中测试离线功能，Lighthouse PWA分数>90

### Story 3.8: 性能优化与最终打磨

作为一个玩家，
我想要应用加载快速、运行流畅，
